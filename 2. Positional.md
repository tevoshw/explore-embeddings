After **understanding** the embeddings, we must know or have an **idea** how they work, 
but now we have a **simple** problem that can ruin all that we learned.

Phrase 1 = 'The cat eats the mouse' 
Phrase 2 = 'The mouse eats the cat'

If we do dot product and attention, the values will be the same. 
So how we gonna know who eats who?


# 1. Positional Encoding

To solve this problem, we can add positional embeddings — vectors that encode 
the position of each token in the sequence. Then we add these positional embeddings 
to the word embeddings, so the model knows both **what** the word is and **where** it is.


# 2. Types

To solve positional encoding, engineers created different techniques.

## 2.1 Absolute Positional Encoding

Each position gets a **fixed embedding** that will be add to the embedding. Position 0, 1, 2, ... each has its own vector.


So it's basically = $embedding_final = embedding + posembedding$

```
Position 0 → [0.1, -0.2, 0.5]
Position 1 → [0.3, 0.4, -0.1]
Position 2 → [0.9, -0.5, 0.2]
```

**Problem:** These new embedding that represents the positional, it's another embedding matrix, and must be have a fixed shape, limiting the sequence in a X number of tokens, in a limit of context that the model can see

## 2.2 Sinusoidal Positional Encoding (Transformer Original)

In sinusoidal, we gonna using the same logic of absolute, but now dont have a fixed limit of tokens in the sequence. The logic

$embeddingfinal = embedding + posembedding$

But now, uses **sin/cos functions** to encode positions. Each dimension oscillates at different frequencies, and dont a fixed matrix
### Understanding Theta (θ)

To calculate Sinusoidal Positional Encoding, we need to understand **theta** — the angle that encodes position.

### Formula

$$\theta = \frac{pos}{10000^{2i/d_{model}}}$$

Where:
- `pos` = Position of the token in the sequence (0, 1, 2, ...)
- `i` = Index of the embedding dimension (0, 1, 2, ...)
- `d_model` = Total dimension of the embedding

### Process

For each position and dimension:

1. **Calculate theta** using the formula above
2. **Apply trigonometric function:**
   - Even dimensions (2i): `PE = sin(θ)`
   - Odd dimensions (2i+1): `PE = cos(θ)`
3. **Get the result:** A value between -1 and 1
4. **Add to embedding:** `embedding_final = word_embedding + PE_value`

### Example

Token at position 2, dimension 0 (i=0), d_model=512:

$$\theta = \frac{2}{10000^{0/512}} = 2 \quad \Rightarrow \quad PE(2,0) = \sin(2) = 0.909$$

Token at position 2, dimension 2 (i=1), d_model=512:

$$\theta = \frac{2}{10000^{2/512}} \approx 0.186 \quad \Rightarrow \quad PE(2,2) = \sin(0.186) = 0.185$$
This 0.185 will be add in the token in position 2 dimension 0, for the others dimensions will be others values.

Each dimension has a **different frequency**, creating rich positional patterns.

**Advantage:** Can extrapolate to longer sequences (generalizes).

**Problem:** Static and learned implicitly by attention.

## 2.3 RoPE (Rotary Position Embedding)

In RoPE, instead of **adding** positional information, we **rotate** the query and key vectors based on position. This encodes **relative distance** between tokens, not absolute position.

$$embedding_{final} = rotate(embedding, \theta)$$

Unlike Sinusoidal, there's no separate positional embedding added. The position is encoded through rotation.

### Why We Use Pairs?

RoPE works on **pairs of dimensions** because a **2D rotation matrix** is the simplest way to apply rotation. We group dimensions into pairs and rotate each pair independently. This is more elegant and computationally efficient than rotating the entire vector at once.

### Understanding Theta (θ) in RoPE

Theta represents the **rotation angle** for each dimension pair.

### Formula

$$\theta_m = 10000^{-2m/d_{model}}$$

Then for each position `pos`:

$$\text{angle} = pos \cdot \theta_m$$

Where:
- `pos` = Position of the token in the sequence (0, 1, 2, ...)
- `m` = Index of the dimension pair (0, 1, 2, ...)
- `d_model` = Total dimension of the embedding

### Matrix Rotation (2D)

For a pair of dimensions, we apply a **2D rotation matrix**:

$$R(\theta) = \begin{pmatrix} \cos(\theta) & -\sin(\theta) \\ \sin(\theta) & \cos(\theta) \end{pmatrix}$$

Applied to a 2D vector `[x, y]`:

$$\begin{pmatrix} \cos(\theta) & -\sin(\theta) \\ \sin(\theta) & \cos(\theta) \end{pmatrix} \begin{pmatrix} x \\ y \end{pmatrix} = \begin{pmatrix} x\cos(\theta) - y\sin(\theta) \\ x\sin(\theta) + y\cos(\theta) \end{pmatrix}$$

**How it works:**
- If `θ > 0`: The vector rotates **θ radians to the left** (counterclockwise)
- If `θ < 0`: The vector rotates **|θ| radians to the right** (clockwise)

The angle `θ` determines how much the embedding vector is rotated based on its position in the sequence.

### Process

For each token at position `pos`:

1. **Calculate base theta** using the formula above (once per dimension pair)
2. **Multiply by position:** `angle = pos * theta_m`
3. **Create rotation matrix:** Using sin and cos of the angle
4. **Apply rotation:** `embedding_rotated = rotation_matrix × word_embedding_pair`

### Example

Token at position 2, dimension pair 0 (m=0), d_model=512:

$$\theta_0 = 10000^{-0/512} = 1$$

$$angle = 2 \times 1 = 2 \text{ radians}$$

$$\text{Rotation matrix: } \begin{pmatrix} \cos(2) & -\sin(2) \\ \sin(2) & \cos(2) \end{pmatrix} = \begin{pmatrix} -0.416 & -0.909 \\ 0.909 & -0.416 \end{pmatrix}$$

Token at position 3, dimension pair 0 (m=0):

$$angle = 3 \times 1 = 3 \text{ radians}$$

The angle difference between position 2 and 3 is **1 radian**, which stays constant **regardless of sequence length**.

### Why RoPE is Better for Long Sequences

**Key insight:** Distance matters, not absolute position.

- Position 2 and 3 are 1 radian apart
- Position 5000 and 5001 are also 1 radian apart

The model sees **relative distances** the same way, so it generalizes perfectly.

### Advantages

- Encodes **relative positions** (better for long sequences)
- No fixed sequence length limit
- Rotational properties allow better extrapolation
- Computationally efficient (applied during attention)

### Problem

- Slightly more complex to implement than Sinusoidal

## 2.4 ALiBi (Attention with Linear Biases)

Doesn't add position embeddings at all. Instead, **biases the attention scores** based on distance.

```
attention_score += -α * |pos_query - pos_key|
```

Closer positions get higher scores, far positions get lower scores.

**Advantage:** Super simple, no extra parameters, works amazingly well on long sequences.
