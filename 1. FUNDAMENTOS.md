# 1. Fundamentos

## 1.1 O que é um vetor

Primeiramente, vamos relembrar o que é um vetor para entender melhor. Um vetor é só uma lista de números. Ponto.

$$[3, 7, -2]$$

Isso é um vetor com 3 números, 3 dimensões.

Um exemplo muito conhecido são as coordenadas. Pensando em longitude e latitude, uma cidade no interior de São Paulo tem coordenadas como `[-21.2, -50.4]`. Isso descreve a localização de uma cidade no mapa — cidades próximas tendem a ter coordenadas parecidas.

## 1.2 Conectando com o embedding

Ao invés de posicionar cidades em um mapa 2D, um embedding posiciona palavras ou frases em um espaço com muitas mais dimensões.

```
"cachorro" → [0.12, -0.44, 0.03, ..., 0.91]   # 384 números
"cão"      → [0.11, -0.42, 0.05, ..., 0.88]   # bem parecido com "cachorro"
"banana"   → [-0.8, 0.3, -0.6, ..., 0.1]      # bem diferente
```

"Cachorro" e "cão" têm números parecidos entre si, porque significam quase a mesma coisa — igual cidades que têm coordenadas parecidas por estarem perto uma da outra. "Banana" fica longe dos dois, porque não tem nada a ver semanticamente.

Ou seja, embedding é um vetor de números, no qual cada coluna representa algo em um espaço.

## 1.3 O que cada coluna representa

Nas coordenadas, cada coluna tem um significado fixo e conhecido: a primeira é latitude (norte/sul), a segunda é longitude (leste/oeste). Um humano definiu isso.

Em um embedding, cada coluna também representa **algo** — alguma característica que ajuda a diferenciar significados — mas esse algo não tem nome nem é definido por humano nenhum. Ele surge **apenas do treinamento** do modelo.

Por exemplo, hipoteticamente:

```
"cachorro" → [1.2, 0.44, 0.9, ..., 0.91]
              ↑      ↑      ↑
           "é vivo" "tamanho" "é fofo"?
```

Pode ser que a coluna 1 acabe capturando algo perto de "é um ser vivo", a coluna 2 algo como "tamanho", e assim por diante. Mas isso é só ilustrativo — na prática, essas combinações costumam ser abstratas demais pra colocar um rótulo humano nelas.



Ou seja: se você treinar um modelo em textos médicos, as colunas vão acabar capturando nuances diferentes de um modelo treinado em código-fonte ou em redes sociais. Não existe coluna com significado universal — existe um padrão que o modelo aprendeu a ser útil, dado o que ele viu durante o treinamento.

## 1.4 Resumo

- Um vetor é uma lista de números.
- Coordenadas geográficas são um exemplo de vetor onde cada coluna tem significado humano fixo.
- Um embedding é um vetor onde cada coluna também representa algo, mas esse "algo" é aprendido automaticamente pelo modelo durante o treinamento — não é definido por uma pessoa e geralmente não é nomeável.
- Palavras/frases com significado parecido acabam com vetores parecidos, assim como cidades próximas têm coordenadas parecidas.
- O que cada coluna captura depende inteiramente dos dados usados no treinamento do modelo.
